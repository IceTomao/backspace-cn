# 聊天视频播放（1.3.23）

## 使用与兼容

MP4、M4V、WebM、MOV 附件在 MIME 缺失或为通用文件类型时按文件名识别，历史消息无需重新上传。已有 `playable=false` 仅显示兼容提示，点击后由设备实际尝试解码。文件后缀不能保证内部编码可播放；无法加载或解码时提供重试和原文件下载。本次没有新增服务器转码。

网页：点击封面或播放按钮开始聊天内播放，系统视频控制栏支持暂停、进度、声音及全屏。同一时间只播放一个聊天视频；点击前不加载视频正文，隐藏页面后释放播放资源，用户再次点击时恢复保存的进度。

安卓：点击视频打开独立原生播放页，使用 Media3 1.11.1 的系统解码器。提供返回、暂停/播放、进度、静音、重试和系统文件选择器下载。系统返回只退出播放器，原聊天保持挂载。切后台或锁屏释放播放器并保存进度，返回后等待用户继续播放；正常旋转保留播放器。没有新增后台视频服务、画中画或权限。

应用前台与 WebView 可见状态继续分开管理，视频页不会让应用误判为后台，也不会主动离开语音频道。通话中视频不主动管理音频焦点，媒体声音使用系统音量。账号退出、服务器切换及视频来源实例断开会关闭播放页。只接受当前或已连接实例的 HTTPS `/api/uploads/` 附件地址，不向媒体请求附加账号凭据，也不跟随外部重定向。

## 服务端与部署

附件 GET 支持单个普通、开放结束和尾部 Range；结束位置超过文件长度时截断。错误或不可满足的单区间返回 `416` 和 `Content-Range: bytes */文件长度`。多区间或不支持的单位返回完整文件。HEAD 返回完整长度且无正文，不打开附件文件流；空文件和媒体 MIME 正确处理。历史通用 MIME 的视频也按文件名纠正，保留非媒体文件与 SVG 的下载规则。

安卓内置页面随 APK 更新；在线网页和附件接口需要部署新版服务器才能获得完整修复。数据库不需要迁移，原附件、账号和数据卷继续使用。

使用本地源码镜像的部署机，在新版源码目录执行：

```sh
docker build -t backspace-cn:1.3.23 .
```

将现有 Portainer Stack 的应用镜像改为 `backspace-cn:1.3.23` 后更新 Stack，保留原域名、端口、环境变量和数据卷。具体部署步骤见 [Portainer 部署说明](PORTAINER_DEPLOY.md)。本次 master 推送自动发布的是 APK；GHCR 容器发行工作流可单独手动运行，以 `1.3.23` 为额外镜像标签。若使用旧的 CDN 附件缓存，部署后检查视频响应的 Content-Type，必要时清除对应旧缓存。
