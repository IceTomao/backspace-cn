# 安卓客户端检查更新

从 1.3.22 起提供安卓客户端检查更新。此前版本需要先手动安装一次 1.3.22，才能使用该入口。

## 使用

- 登录后：我 → 设置 → 设备外观 → 应用更新。登录页的服务器设置、连接失败的恢复页也提供入口。
- 显示实际安装 APK 的版本，不以服务器版本代替。点击“检查更新”立即查询；发现新版可点击“下载更新”。
- 下载交给浏览器，完成后打开 APK 并按系统提示安装。如系统要求，为下载使用的浏览器或文件管理器允许“安装未知应用”。同包名、同发行签名且版本递增的 APK 可覆盖安装。
- 更新提示可选择“稍后提醒”，当前版本的提示不再自动显示，设置页仍能下载；更高版本发布后重新提示。
- 不进行静默安装，也不申请 `REQUEST_INSTALL_PACKAGES` 权限。debug 包使用独立包名，不参与正式版更新。

## 检查频率与来源

自动检查在网页可见的前台启动或恢复时触发，成功后至少间隔 24 小时，失败后至少间隔 6 小时；手动检查不受间隔限制。并发检查合并为同一请求，没有后台定时器或消息轮询。网络请求最多等待 25 秒，失败可手动重试。

原生通过公开 GitHub Releases API 读取 `IceTomao/backspace-cn` 最近 100 条发行记录，只接受 `android-vX.Y.Z` 正式版本及对应已上传、非空 APK。下载地址限定为该仓库的版本化发行附件，不使用服务器下发地址。草稿、预发行、Windows 发行及版本不高于已安装 APK 的记录不会提示升级。没有有效 APK 时显示暂未提供安装包，不会误报已是最新版。

## 自动发布

递增所有包版本后提交并推送 master，现有 Android APK workflow 构建固定签名发行包，验证包名、版本和证书，再发布独立标签 `android-vX.Y.Z`。附件包含版本化 APK、其 SHA256 和 APK 验证报告。附件齐全后才公开草稿；已发布的同版本 APK不会被后续构建替换，功能变更应继续递增版本。

安卓发行设置 `make_latest=false`，沿用独立标签，避免覆盖 Windows 的 latest 更新来源。签名 Secrets 已配置，更新发布使用 workflow 的仓库写入权限，不需要额外私人 token。密钥备份仍按 [固定签名说明](ANDROID_SIGNING.md) 保存。

## 验证范围

自动测试覆盖版本与附件筛选、降级防止、每日检查、失败重试、并发合并、提示忽略持久化、网页隐藏与监听释放，以及检查/下载 UI。360/412 像素浅深主题使用模拟原生桥验证布局和交互。实际手机的浏览器下载、系统安装提示和覆盖更新仍需真机验收。
